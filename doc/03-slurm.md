# Stage 3: Slurm (Ansible)

Install and configure Slurm on the 4 servers from stage 2 ([02-vms.md](02-vms.md)), with
Ansible running on the workstation. The setup follows the on-prem notes (Slurm 25.11.3 built
from source, munge uid/gid 791, slurm uid/gid 792, `/usr/local/slurm`, `/etc/slurm`), as the
earlier test cluster in `aws-infra` did. The same playbook can later be pointed at on-prem
servers by changing only the inventory.

## Target (end of stage 3)

| Server | Slurm role | Services |
|---|---|---|
| slurm-master | controller + accounting | `slurmctld`, `slurmdbd`, `mariadb`, `munge` |
| slurm-node-1..3 | compute nodes | `slurmd`, `munge` |

`sinfo` shows partition `debug` with slurm-node-[1-3] idle; `srun -N3 hostname` runs on all
three; `sacct` lists the jobs.

## Terraform vs Ansible

| | Terraform (stages 1-2) | Ansible (stage 3) |
|---|---|---|
| Works on | AWS (VPC, instances, ...) | inside the servers (packages, files, services) |
| Talks to | the AWS API | each server over SSH |
| Remembers | state file | nothing: checks the server each run |
| Re-run | changes only what differs from the state | skips tasks that are already done ("ok") |

## Step 3.1: Ansible setup and inventory

Ansible needs to know **which servers** exist (the *inventory*) and **how to log in**
(`ansible.cfg`). Then `ansible all -m ping` logs in to every server and checks that Python works.

**Files:**

| File | In git? | What |
|---|---|---|
| `slurm/ansible/ansible.cfg` | yes | inventory file, user `ec2-user`, key `~/.ssh/slurm-dev-key` |
| `slurm/ansible/make-inventory.sh` | yes | writes `inventory.ini` from `terraform output instances` |
| `slurm/ansible/inventory.ini` | **no** (generated) | the servers and their private IPs, in groups |
| `.gitattributes` | yes | keeps `*.sh` and `Makefile` with Linux line endings |

**ansible.cfg:**

| Setting | Value | Why |
|---|---|---|
| `inventory` | inventory.ini | the generated file |
| `remote_user` | ec2-user | default user on RHEL AMIs; has sudo without password |
| `private_key_file` | ~/.ssh/slurm-dev-key | the key from step 2.1 |
| `host_key_checking` | False | re-created servers get new host keys (same reason as `make ssh`) |
| `interpreter_python` | auto_silent | use the server's Python 3 without a warning |

**Generated inventory** (example; the IPs come from Terraform):

```ini
# Generated by 'make inventory' from the Terraform outputs. Do not edit by hand.
[master]
slurm-master ansible_host=172.21.10.25

[nodes]
slurm-node-1 ansible_host=172.21.10.41
slurm-node-2 ansible_host=172.21.10.87
slurm-node-3 ansible_host=172.21.10.140
```

- `[master]` and `[nodes]` are **groups**; a play can target `hosts: master`, `hosts: nodes`, or
  `hosts: all`.
- `slurm-master` is the **inventory name**; Ansible uses it in output and stage 3.2 makes it the
  real hostname. `ansible_host` is the address it connects to.
- The old `aws-infra` inventory had hand-copied public IPs that broke after every re-create.
  This one is rewritten from Terraform before every Ansible run, so it is never out of date.

**Make targets:**

| Command | What |
|---|---|
| `make inventory` | runs `make-inventory.sh` and prints the inventory |
| `make ping` | `make inventory`, then `ansible all -m ping` |

**Run on the workstation:**

```bash
cd ~/workstation- && git pull && cd slurm
make output        # 4 instances must exist (stage 2)
ansible --version  # installed in the workstation setup (pip, ~/.local/bin)
make ping
```

Expected, once per server:

```
slurm-master | SUCCESS => {
    "changed": false,
    "ping": "pong"
}
```

`ping` here is not ICMP ping: Ansible logs in over SSH, runs a small Python module and gets
`pong` back. It proves SSH, the key, sudo-less login and Python all work.

| Error | Check |
|---|---|
| `UNREACHABLE ... timed out` | `make ssh HOST=<name>` works? (peering, security group) |
| `Permission denied (publickey)` | `~/.ssh/slurm-dev-key` exists; key pair `slurm-dev-key` on the instances |
| `No outputs found` / jq error | `make output` shows `instances`; run from `~/workstation-/slurm` |
| `ansible: command not found` | `export PATH=$HOME/.local/bin:$PATH` (see Workstation-Setup.docx) |
| `bash\r: No such file or directory` | script got Windows line endings; `.gitattributes` prevents this |

**Nothing is changed on the servers in this step.**

**Result (2026-10-26):** all 4 servers `SUCCESS` / `pong`, Python `/usr/bin/python3.9`.
`make plan` afterwards: `No changes. Your infrastructure matches the configuration.`

## Step 3.2: Base OS

The first playbook that **changes** the servers: the OS settings every Slurm server needs.

**New files:**

| File | What |
|---|---|
| `slurm/ansible/slurm.yml` | the **playbook**: a list of *plays*; each play = which hosts + a list of *tasks* |
| `slurm/ansible/group_vars/all.yml` | variables for all servers, loaded automatically (because of the folder name) |

New make target: `make ansible-slurm` (= `make inventory`, then `ansible-playbook slurm.yml`).

**Play `Base OS`** (`hosts: all`, `become: true` = run as root via sudo, tag `base`):

| Task | Module | What it does | Why |
|---|---|---|---|
| Set hostname | `hostname` | `slurm-master`, `slurm-node-1`, ... (the inventory name) | Slurm identifies nodes by hostname |
| Keep the hostname | `copy` | `/etc/cloud/cloud.cfg.d/99-preserve-hostname.cfg` | otherwise cloud-init resets it to `ip-172-21-...` at boot |
| /etc/hosts | `lineinfile` + `loop` | one line per server: `172.21.10.x slurm-node-1` | servers find each other by name, no DNS needed |
| Swap file | `command` (`creates:`), `file`, `lineinfile` | 2 GB `/swapfile`, on now and at boot | nodes have 1 GB RAM; dnf ran out of memory without it |
| SELinux permissive | `ansible.posix.selinux` | permissive now and in `/etc/selinux/config` | Slurm/munge from `/usr/local` are blocked in enforcing mode (same as on-prem) |
| firewalld off | `service_facts` + `systemd_service` | stopped + disabled, **only if installed** | the security group is the firewall |
| munge / slurm users | `group`, `user` + `loop` | munge 791, slurm 792, no login shell, no home | same IDs as on-prem |

**Ideas in this playbook:**

- **Modules** do one job each (`hostname`, `copy`, `lineinfile`, `user`, ...) and check first:
  if the server is already right, the task reports `ok` and changes nothing.
- **Idempotent:** running the playbook again gives the same result. Tasks that run commands
  use `creates:` (skip if a file exists) or `when:` (skip if a condition is false) to stay idempotent.
- **`loop`** repeats a task for each item; `{{ item }}` is the current one.
- **Facts:** at the start, Ansible collects information about each server ("Gathering Facts"),
  e.g. `ansible_facts['swaptotal_mb']`. `when:` uses it to decide.
- **`register`** saves a task's result (`swapfile.changed`) for later tasks.
- **`hostvars[item].ansible_host`** reads another server's inventory value (its IP).
- **Tags** (`base`) let you run only part of the playbook: `ARGS="--tags base"`.

**Run on the workstation:**

```bash
cd ~/workstation- && git pull && cd slurm
make ansible-slurm ARGS="--check --diff"   # dry run: shows what would change, changes nothing
make ansible-slurm                         # real run
make ansible-slurm                         # again: everything "ok", changed=0
```

Read the **PLAY RECAP** at the end:

```
slurm-master : ok=12  changed=8  unreachable=0  failed=0  skipped=1 ...
```

| Word | Meaning |
|---|---|
| `ok` | task ran, server already correct |
| `changed` | task changed something |
| `skipped` | `when:` was false (e.g. firewalld not installed) |
| `failed` / `unreachable` | must be 0 |

In `--check` mode, `command` tasks are skipped (Ansible cannot know what a command would do),
so the dry run shows fewer changes than the real run.

**Check on a server:**

```bash
make ssh HOST=slurm-node-1
hostname                       # slurm-node-1 (prompt changes at next login)
cat /etc/hosts                 # 4 cluster lines
free -m                        # Swap: 2047
getenforce                     # Permissive
id munge; id slurm             # uid=791(munge) ..., uid=792(slurm) ...
ping -c1 slurm-master          # name works between servers
exit
```

If `ansible.posix.selinux` is not found: the workstation has only `ansible-core`. The full
`ansible` pip package (installed in the workstation setup) includes `ansible.posix`.
Check with `ansible-galaxy collection list | grep posix`.
