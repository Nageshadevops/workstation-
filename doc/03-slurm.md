# Stage 3: Slurm (Ansible)

Install and configure Slurm on the 4 servers from stage 2 ([02-vms.md](02-vms.md)), with
Ansible running on the workstation. The setup follows the on-prem notes (Slurm 25.11.3 built
from source, munge uid/gid 791, slurm uid/gid 792, `/usr/local/slurm`, `/etc/slurm`), as the
earlier test cluster in `aws-infra` did. The same playbook can later be pointed at on-prem
servers by changing only the inventory.

## Target (end of stage 3)

| Server | Slurm role | Services |
|---|---|---|
| slurm-master | controller + accounting | `slurmctld`, `slurmdbd`, `mariadb`, `munge` |
| slurm-node-1..3 | compute nodes | `slurmd`, `munge` |

`sinfo` shows partition `debug` with slurm-node-[1-3] idle; `srun -N3 hostname` runs on all
three; `sacct` lists the jobs.

## Terraform vs Ansible

| | Terraform (stages 1-2) | Ansible (stage 3) |
|---|---|---|
| Works on | AWS (VPC, instances, ...) | inside the servers (packages, files, services) |
| Talks to | the AWS API | each server over SSH |
| Remembers | state file | nothing: checks the server each run |
| Re-run | changes only what differs from the state | skips tasks that are already done ("ok") |

## Step 3.1: Ansible setup and inventory

Ansible needs to know **which servers** exist (the *inventory*) and **how to log in**
(`ansible.cfg`). Then `ansible all -m ping` logs in to every server and checks that Python works.

**Files:**

| File | In git? | What |
|---|---|---|
| `slurm/ansible/ansible.cfg` | yes | inventory file, user `ec2-user`, key `~/.ssh/slurm-dev-key` |
| `slurm/ansible/make-inventory.sh` | yes | writes `inventory.ini` from `terraform output instances` |
| `slurm/ansible/inventory.ini` | **no** (generated) | the servers and their private IPs, in groups |
| `.gitattributes` | yes | keeps `*.sh` and `Makefile` with Linux line endings |

**ansible.cfg:**

| Setting | Value | Why |
|---|---|---|
| `inventory` | inventory.ini | the generated file |
| `remote_user` | ec2-user | default user on RHEL AMIs; has sudo without password |
| `private_key_file` | ~/.ssh/slurm-dev-key | the key from step 2.1 |
| `host_key_checking` | False | re-created servers get new host keys (same reason as `make ssh`) |
| `interpreter_python` | auto_silent | use the server's Python 3 without a warning |

**Generated inventory** (example; the IPs come from Terraform):

```ini
# Generated by 'make inventory' from the Terraform outputs. Do not edit by hand.
[master]
slurm-master ansible_host=172.21.10.25

[nodes]
slurm-node-1 ansible_host=172.21.10.41
slurm-node-2 ansible_host=172.21.10.87
slurm-node-3 ansible_host=172.21.10.140
```

- `[master]` and `[nodes]` are **groups**; a play can target `hosts: master`, `hosts: nodes`, or
  `hosts: all`.
- `slurm-master` is the **inventory name**; Ansible uses it in output and stage 3.2 makes it the
  real hostname. `ansible_host` is the address it connects to.
- The old `aws-infra` inventory had hand-copied public IPs that broke after every re-create.
  This one is rewritten from Terraform before every Ansible run, so it is never out of date.

**Make targets:**

| Command | What |
|---|---|
| `make inventory` | runs `make-inventory.sh` and prints the inventory |
| `make ping` | `make inventory`, then `ansible all -m ping` |

**Run on the workstation:**

```bash
cd ~/workstation- && git pull && cd slurm
make output        # 4 instances must exist (stage 2)
ansible --version  # installed in the workstation setup (pip, ~/.local/bin)
make ping
```

Expected, once per server:

```
slurm-master | SUCCESS => {
    "changed": false,
    "ping": "pong"
}
```

`ping` here is not ICMP ping: Ansible logs in over SSH, runs a small Python module and gets
`pong` back. It proves SSH, the key, sudo-less login and Python all work.

| Error | Check |
|---|---|
| `UNREACHABLE ... timed out` | `make ssh HOST=<name>` works? (peering, security group) |
| `Permission denied (publickey)` | `~/.ssh/slurm-dev-key` exists; key pair `slurm-dev-key` on the instances |
| `No outputs found` / jq error | `make output` shows `instances`; run from `~/workstation-/slurm` |
| `ansible: command not found` | `export PATH=$HOME/.local/bin:$PATH` (see Workstation-Setup.docx) |
| `bash\r: No such file or directory` | script got Windows line endings; `.gitattributes` prevents this |

**Nothing is changed on the servers in this step.**

**Result (2026-10-26):** all 4 servers `SUCCESS` / `pong`, Python `/usr/bin/python3.9`.
`make plan` afterwards: `No changes. Your infrastructure matches the configuration.`

## Step 3.2: Base OS

The first playbook that **changes** the servers: the OS settings every Slurm server needs.

**New files:**

| File | What |
|---|---|
| `slurm/ansible/slurm.yml` | the **playbook**: a list of *plays*; each play = which hosts + a list of *tasks* |
| `slurm/ansible/group_vars/all.yml` | variables for all servers, loaded automatically (because of the folder name) |

New make target: `make ansible-slurm` (= `make inventory`, then `ansible-playbook slurm.yml`).

**Play `Base OS`** (`hosts: all`, `become: true` = run as root via sudo, tag `base`):

| Task | Module | What it does | Why |
|---|---|---|---|
| Set hostname | `hostname` | `slurm-master`, `slurm-node-1`, ... (the inventory name) | Slurm identifies nodes by hostname |
| Keep the hostname | `copy` | `/etc/cloud/cloud.cfg.d/99-preserve-hostname.cfg` | otherwise cloud-init resets it to `ip-172-21-...` at boot |
| /etc/hosts | `lineinfile` + `loop` | one line per server: `172.21.10.x slurm-node-1` | servers find each other by name, no DNS needed |
| Swap file | `shell` (`creates:`), `command`, `lineinfile` | 2 GB `/swapfile` (dd + chmod 600 + mkswap in one task), on now and at boot | nodes have 1 GB RAM; dnf ran out of memory without it |
| SELinux permissive | `ansible.posix.selinux` | permissive now and in `/etc/selinux/config` | Slurm/munge from `/usr/local` are blocked in enforcing mode (same as on-prem) |
| firewalld off | `service_facts` + `systemd_service` | stopped + disabled, **only if installed** | the security group is the firewall |
| munge / slurm users | `group`, `user` + `loop` | munge 791, slurm 792, no login shell, no home | same IDs as on-prem |

**Ideas in this playbook:**

- **Modules** do one job each (`hostname`, `copy`, `lineinfile`, `user`, ...) and check first:
  if the server is already right, the task reports `ok` and changes nothing.
- **Idempotent:** running the playbook again gives the same result. Tasks that run commands
  use `creates:` (skip if a file exists) or `when:` (skip if a condition is false) to stay idempotent.
- **`loop`** repeats a task for each item; `{{ item }}` is the current one.
- **Facts:** at the start, Ansible collects information about each server ("Gathering Facts"),
  e.g. `ansible_facts['swaptotal_mb']`. `when:` uses it to decide.
- **`creates:`** on `command`/`shell`: skip the task if that file already exists.
- **`hostvars[item].ansible_host`** reads another server's inventory value (its IP).
- **Tags** (`base`) let you run only part of the playbook: `ARGS="--tags base"`.

**Run on the workstation:**

```bash
cd ~/workstation- && git pull && cd slurm
make ansible-slurm ARGS="--check --diff"   # dry run: shows what would change, changes nothing
make ansible-slurm                         # real run
make ansible-slurm                         # again: everything "ok", changed=0
```

Read the **PLAY RECAP** at the end:

```
slurm-master : ok=12  changed=8  unreachable=0  failed=0  skipped=1 ...
```

| Word | Meaning |
|---|---|
| `ok` | task ran, server already correct |
| `changed` | task changed something |
| `skipped` | `when:` was false (e.g. firewalld not installed) |
| `failed` / `unreachable` | must be 0 |

In `--check` mode, `command` and `shell` tasks are skipped (Ansible cannot know what a command
would do); with `creates:` they are only *reported* as `changed`, without running.

**Lesson learned (2026-10-26):** the first dry run failed at "Swap file permissions":
`file (/swapfile) is absent, cannot continue`. In check mode `dd` did not really create
`/swapfile`, so the next task (`file` with `mode: 0600`) found nothing. Nothing was changed on
the servers (dry run). Fix: create, chmod and mkswap the file in **one** `shell` task with
`creates: /swapfile`, so no later task depends on a file a skipped command should have made.

**Check on a server:**

```bash
make ssh HOST=slurm-node-1
hostname                       # slurm-node-1 (prompt changes at next login)
cat /etc/hosts                 # 4 cluster lines
free -m                        # Swap: 2047
getenforce                     # Permissive
id munge; id slurm             # uid=791(munge) ..., uid=792(slurm) ...
ping -c1 slurm-master          # name works between servers
exit
```

If `ansible.posix.selinux` is not found: the workstation has only `ansible-core`. The full
`ansible` pip package (installed in the workstation setup) includes `ansible.posix`.
Check with `ansible-galaxy collection list | grep posix`.

**Result (2026-10-26):** real run `failed=0` on all 4; second run `ok=10 changed=0 skipped=2`
on all 4 (idempotent). firewalld is not installed on these RHEL images (task skipped).
slurm-node-1 shows hostname `slurm-node-1` at login.

## Step 3.3: Packages + munge

**munge** is how Slurm servers prove who they are. Every message between Slurm daemons carries
a munge *credential*, signed with a secret key. A server accepts it only if it has the
**same key** and its clock is close (credentials expire after a few minutes).

**Variables** (`group_vars/all.yml`): `crb_repo` and `slurm_packages` (list from the on-prem notes).

**Four new plays in `slurm.yml`:**

| Play | Hosts | Tag | Tasks |
|---|---|---|---|
| Packages | all | `packages` | enable CodeReady Builder repo; install `slurm_packages` |
| Munge key on the master | master | `munge` | create `/etc/munge/munge.key` (once); read it into memory |
| Munge on every server | all | `munge` | copy the key to the nodes; folder owners; start + enable munge |
| Munge test | all | `munge` | `munge -n` on the master, `unmunge` of that credential on every server |

Details:

- **CodeReady Builder (CRB):** Red Hat repo with most `-devel` packages, off by default.
  `community.general.dnf_config_manager` = `dnf config-manager --set-enabled ...`, but idempotent.
- **Packages on every server:** Slurm is compiled once on the master (step 3.4); the nodes need
  the same runtime libraries. The `-devel` packages pull them in.
- **Order matters:** the `munge` user (uid 791) was created in step 3.2 **before** the munge
  package. The package then uses the existing user instead of creating one with a random uid.
- **The key:** 1024 random bytes, stored as base64 text (`head -c 1024 /dev/urandom | base64 -w0`),
  owner munge, mode 0400. Created only if missing (`creates:`), so re-runs keep the same key.
  RHEL 9's munge 0.5.13 has no `mungekey` command.
- **Copying a secret without a file:** `slurp` reads the key from the master into Ansible's
  memory, and `copy content:` writes it on the nodes. The old `aws-infra` code fetched it to
  `ansible/files/munge.key` on the laptop; now the secret never touches the workstation's disk.
  `no_log: true` keeps it out of the output.
- **Handlers:** `notify: Restart munge` queues a restart; the handler runs **once** at the end of
  the play, and only if the key actually changed.
- **`hostvars[groups['master'][0]].munge_key`:** a node reads a variable registered on the
  master in an earlier play.
- **The test** is part of the playbook, so every run proves munge works across servers.
  `changed_when: false`: a check is never a change.

**Run on the workstation:**

```bash
cd ~/workstation- && git pull && cd slurm
make ansible-slurm ARGS="--check --diff --tags packages"   # dry run of the package part only
make ansible-slurm      # real run; the package install takes a few minutes per node
make ansible-slurm      # again: changed=0
```

**Lesson learned (2026-10-26):** even the packages-only dry run fails the first time:
`No package munge-devel available` (also lua-devel, rrdtool-devel, mariadb-devel, json-c-devel,
libbpf-devel). Those six are exactly the packages in CodeReady Builder. In check mode the repo
task only *reports* that it would enable CRB, so the simulated `dnf` still cannot see them.
Check without changing anything:
`sudo dnf -q --enablerepo=codeready-builder-for-rhel-9-rhui-rpms list available munge-devel ...`
(`--enablerepo` turns the repo on for that one command only). Then run for real.

A dry run of the **whole** playbook fails before the first real run: munge is not installed
yet, so "Start munge" cannot find the service. `--check` cannot simulate a service that an
earlier task *would* install. The tasks that need the real key or a running munge are skipped
in check mode (`when: not ansible_check_mode`).

**Expected:** task "Decode the master's credential on every server" → `ok` on all 4.

**Check by hand** (on slurm-master):

```bash
make ssh
sudo md5sum /etc/munge/munge.key                  # remember the checksum
munge -n | unmunge | grep STATUS                  # STATUS: Success (0)
exit
make ssh HOST=slurm-node-2
sudo md5sum /etc/munge/munge.key                  # same checksum as the master
systemctl is-active munge                         # active
exit
```

| Error | Cause |
|---|---|
| `No package ... available` | CRB repo not enabled; check `dnf repolist` on the node |
| dnf killed / out of memory on a node | swap from step 3.2 missing: `free -m` |
| `unmunge: Error: Invalid credential` | keys differ: compare `md5sum` |
| `unmunge: Error: Expired credential` | clocks differ: `timedatectl` (chronyd should be active) |

**Result (2026-10-26):** packages installed and munge test `ok` on all 4. Second run:
`changed=0 failed=0` (master ok=22 skipped=3, nodes ok=19 skipped=3).

## Step 3.4: Build Slurm

Slurm 25.11.3 is built from source, exactly like the on-prem notes (steps 11-14 in
`slurmconfigurationsetup.txt`), but only **once, on the master**. The result is packed and
unpacked on the nodes: they have only 1 GB RAM, and one build guarantees identical binaries.

```
slurm-master: download -> configure -> make -> make install -> tar czf slurm-install-25.11.3.tgz
                                                                         |  fetch
                                                                         v
                                              workstation: slurm/ansible/files/ (git-ignored)
                                                                         |  unarchive
                                                                         v
                                              slurm-node-1..3: /usr/local/slurm
```

The package goes through the workstation because the servers cannot SSH to each other yet
(step 3.8). It is about 140 MB (built with `--enable-debug`), not secret.

**Variables** (`group_vars/all.yml`):

| Variable | Value |
|---|---|
| `slurm_version` | 25.11.3 |
| `slurm_prefix` | /usr/local/slurm |
| `slurm_sysconfdir` | /etc/slurm |
| `slurm_marker` | /usr/local/slurm/.installed-25.11.3 |

**Plays** (tag `build`):

| Play | Hosts | Tasks |
|---|---|---|
| Build Slurm on the master | master | Development Tools; download `slurm-25.11.3.tar.bz2`; unpack; `./configure --prefix=/usr/local/slurm --sysconfdir=/etc/slurm --with-munge --enable-debug`; `make -j$(nproc) && make install`; `tar czf`; `fetch` to the workstation |
| Install Slurm on the nodes | nodes | `unarchive` the package into `/usr/local` |
| Slurm build test | all | `slurmd -V` must print 25.11.3 |

Ideas:

- **Marker file for upgrades:** `make install` creates `/usr/local/slurm/.installed-25.11.3`
  and every install task has `creates:` on it. Re-runs skip the build. If `slurm_version` is
  changed later, there is no marker for the new version, so it is downloaded, built and
  installed again: an upgrade is one variable change.
- **`async` + `poll`:** the compile runs in the background on the master and Ansible checks every
  30 seconds, so a 10-15 minute task does not depend on one long SSH session.
- **`get_url`, `unarchive` (`remote_src: true`), `fetch`:** download on the server, unpack a
  file that is already on the server, copy a file from a server to the workstation.
- **`failed_when`:** the test fails only if the version text is missing from the output.

**Run on the workstation:**

```bash
cd ~/workstation- && git pull && cd slurm
make ansible-slurm      # ~15-20 minutes the first time (the compile is the slow part)
make ansible-slurm      # again: changed=0, about 1 minute
ls -lh ansible/files/   # slurm-install-25.11.3.tgz on the workstation
```

During "Compile and install" Ansible prints `ASYNC POLL on slurm-master: jid=... started=1
finished=0` every 30 s; that is normal.

No dry run for this step: `--check` cannot download or compile, so it would fail at the first
task that needs the source.

**Check by hand:**

```bash
make ssh HOST=slurm-node-2
ls /usr/local/slurm               # bin  include  lib  sbin  share
/usr/local/slurm/bin/sinfo -V     # slurm 25.11.3
exit
```

`sinfo` itself does not work yet (no `slurm.conf`, no PATH): that is step 3.6.

| Error | Check |
|---|---|
| `configure: error: ... munge` | munge-devel installed? (step 3.3) |
| compile killed / out of memory | swap on the master: `free -m` |
| download fails | NAT gateway; `curl -sI https://download.schedmd.com` on the master |
| `async task did not complete within the requested time` | rerun; the build continues where `make` stopped |

**Result (2026-10-26):** compile ~10 minutes; recap master `changed=7`, nodes `changed=1`,
`failed=0`; version check `ok` on all 4.

## Step 3.5: Accounting database (MariaDB + slurmdbd)

Slurm keeps job history (who ran what, how long, how much CPU) in a database. Three programs
on the master:

```
slurmctld (step 3.6) --> slurmdbd :6819 --> MariaDB :3306
                         accounting         database slurm_acct_db
                         daemon             user slurm@localhost
```

On-prem, slurmdbd runs on a separate server (172.16.3.14); here it shares the master.

**Files:**

| File | What |
|---|---|
| `slurm/ansible/templates/slurmdbd.conf.j2` | slurmdbd settings; becomes `/etc/slurm/slurmdbd.conf` |
| `slurm/ansible/templates/slurmdbd.service.j2` | systemd service; becomes `/etc/systemd/system/slurmdbd.service` |
| `group_vars/all.yml` | `slurmdbd_port`, `slurmdbd_db_name`, `slurmdbd_db_user`, `slurmdbd_db_password_file` |

A **template** (`.j2`, Jinja2) is a file with `{{ variables }}` that Ansible fills in for each
server; `template:` writes the result and reports `changed` only if it differs.

**Play `Accounting database`** (master, tag `slurmdbd`):

| Task | What |
|---|---|
| MariaDB | install `mariadb-server`; `/etc/my.cnf.d/innodb.cnf` (SchedMD's settings); start + enable; `flush_handlers` so a restart for new settings happens **before** slurmdbd creates its tables |
| Password | generated once with `openssl rand` into `/root/.slurmdbd_db_password` (mode 600), read with `slurp`, kept in a variable with `set_fact` |
| Database + user | `mysql -u root` with SQL on stdin: `CREATE DATABASE IF NOT EXISTS`, `CREATE USER IF NOT EXISTS`, `ALTER USER ... IDENTIFIED BY` (password always in sync), `GRANT` |
| slurmdbd | `/etc/slurm` and `/var/log/slurm` (owner slurm); `slurmdbd.conf` (mode 600, owner slurm); service file; start + enable; wait until port 6819 is open |

**No password in git.** The old `aws-infra` had `slurmdbd_db_password: "ChangeMe123"` in
`vars.yml`. Now it is made on the master the first time, like the munge key, and every run reads
it from there. Nobody types or stores it. Protection:

- `/root/.slurmdbd_db_password` and `/etc/slurm/slurmdbd.conf` are readable only by root / slurm.
- `no_log: true` on the tasks that handle it, and `diff: false` on the template, so it never
  appears in Ansible output, not even with `--diff`.
- To read it (as root on the master): `sudo cat /root/.slurmdbd_db_password`.

**New ideas:** `template`, `set_fact` (make a variable during the run), `meta: flush_handlers`
(run queued handlers now instead of at the end), `wait_for` (wait for a port), `diff: false`.

**Run on the workstation:**

```bash
cd ~/workstation- && git pull && cd slurm
make ansible-slurm      # ~2 minutes
make ansible-slurm      # again: changed=0
```

**Check by hand** (on slurm-master):

```bash
make ssh
systemctl is-active mariadb slurmdbd        # active active
sudo ss -ltnp | grep -E '3306|6819'         # mariadbd on 3306, slurmdbd on 6819
sudo tail -5 /var/log/slurm/slurmdbd.log    # no errors; tables created
sudo ls -l /etc/slurm/slurmdbd.conf         # -rw------- slurm slurm
sudo mysql -e 'SHOW DATABASES;'             # slurm_acct_db
exit
```

| Error | Check |
|---|---|
| `wait_for` times out on 6819 | `sudo tail -30 /var/log/slurm/slurmdbd.log` |
| log: `Access denied for user 'slurm'@'localhost'` | password file and `StoragePass` differ: rerun the playbook (ALTER USER syncs it) |
| log: `slurmdbd.conf file ... should be 600` | file mode; the template sets 0600 |
| log: `Can't connect to local MySQL server` | `systemctl status mariadb` |

**Result (2026-10-26):** mariadb and slurmdbd active. slurmdbd.log: started, one SIGTERM
(the handler restart for the new config on the first run, expected), connected to MariaDB 10.5.29.

It also logs `error: Database settings not recommended values: innodb_buffer_pool_size`.
This is a warning, not a failure: slurmdbd keeps running. MariaDB really uses our value
(`SELECT @@innodb_buffer_pool_size/1024/1024` → 512); slurmdbd recommends more for production.
Kept at 512 MB on purpose: the master has 4 GB RAM and also runs slurmctld; a test cluster
needs far less. On a dedicated database server (as on-prem), use a larger value.

## Step 3.6: slurm.conf + services → sinfo

Now Slurm gets its configuration and its daemons start:

| Server | Daemon | Port | Job |
|---|---|---|---|
| slurm-master | `slurmctld` | 6817 | the controller: knows all nodes, queues and schedules jobs |
| slurm-node-1..3 | `slurmd` | 6818 | runs the jobs; registers with slurmctld at start |

**Files:**

| File | Becomes | Where |
|---|---|---|
| `templates/slurm.conf.j2` | `/etc/slurm/slurm.conf` | all (identical) |
| (inline) | `/etc/slurm/cgroup.conf` = `CgroupPlugin=autodetect` | all |
| (inline) | `/etc/profile.d/slurm.sh` (PATH) | all |
| `templates/slurmctld.service.j2` | `/etc/systemd/system/slurmctld.service` | master |
| `templates/slurmd.service.j2` | `/etc/systemd/system/slurmd.service` (from the on-prem notes) | nodes |
| `group_vars/master.yml` | `slurm_service: slurmctld` | |
| `group_vars/nodes.yml` | `slurm_service: slurmd` | |

**Group variables:** the same tasks run everywhere, but `slurm_service` has a different value
per group, because Ansible loads `group_vars/master.yml` for servers in `[master]` and
`group_vars/nodes.yml` for servers in `[nodes]`. So "Install the {{ slurm_service }} service"
installs slurmctld on the master and slurmd on the nodes.

**slurm.conf** (same settings as the on-prem file, see `slurm configurations.txt` in aws-infra):

| Setting | Value | Note |
|---|---|---|
| `ClusterName` | slurmcluster | as on-prem |
| `SlurmctldHost` | slurm-master(172.21.10.x) | on-prem: slurmcluster |
| `AuthType` | auth/munge | as on-prem |
| `ProctrackType` / `TaskPlugin` | cgroup / affinity,cgroup | as on-prem |
| `SchedulerType` | sched/backfill | as on-prem |
| `SelectType` | cons_tres, CR_Core | as on-prem |
| `AccountingStorageHost` | slurm-master | on-prem: separate DB server 172.16.3.14 |
| `PrologFlags` / `X11Parameters` | X11 / home_xauthority | on-prem also has `Prolog=/etc/slurm/prolog.sh` (not used here) |
| `ReturnToService` | 2 | on-prem 0; nodes come back after a reboot without `scontrol` |
| `SlurmctldPidFile` | /run/slurmctld/slurmctld.pid | slurmctld runs as user slurm and cannot write `/var/run` |
| Nodes | from facts, `RealMemory` = 90% of RAM | e.g. t3.micro: 1 socket, 1 core, 2 threads, 2 CPUs |
| Partition | `debug` = slurm-node-1,2,3, default, no time limit | on-prem: short/long/gui per OS |

The node lines are built with a Jinja2 **`{% for %}` loop** over `groups['nodes']`, using each
node's facts (`processor_count`, `processor_cores`, `processor_threads_per_core`,
`processor_vcpus`, `memtotal_mb`). Adding a node in Terraform + rerunning Ansible adds its line.

## Step 3.7: Accounting (cluster, account, users)

slurmdbd stores **associations**: cluster → account → user. A job is recorded under the user's
default account; reports (`sreport`) and later limits or fair-share work per association.

| Level | Value |
|---|---|
| cluster | slurmcluster (registered by slurmctld itself; the play adds it if missing) |
| account | `default` (`slurm_account`) |
| users | `root`, `ec2-user` (`slurm_users`) |

Accounting is **recorded but not enforced** (`AccountingStorageEnforce` is not set, as on-prem):
users without an association can still run jobs; their jobs just have no account.

**Play `Accounting`** (master, tag `accounting`). For each level: read what exists, add only
what is missing:

| Read | Add (only if missing) |
|---|---|
| `sacctmgr -n -P show cluster format=cluster` | `sacctmgr -i add cluster slurmcluster` |
| `sacctmgr -n -P show account format=account` | `sacctmgr -i add account default Cluster=slurmcluster` |
| `sacctmgr -n -P show association where account=default format=user` | `sacctmgr -i add user <user> Account=default Cluster=slurmcluster` (loop over `slurm_users`) |

`-n` = no header, `-P` = plain output (one value per line), `-i` = do not ask for confirmation.
`environment: PATH` puts `/usr/local/slurm/bin` on the PATH for these tasks.

The old `aws-infra` ran `sacctmgr add` every time with `failed_when: false`, which hides real
errors. Reading first keeps it idempotent **and** lets real errors fail the run.

**Add a user later:** the Linux user must exist on every server (same uid), then add it to
`slurm_users` in `group_vars/all.yml` and run `make ansible-slurm ARGS="--tags accounting"`.

**Run on the workstation:**

```bash
cd ~/workstation- && git pull && cd slurm
make ansible-slurm ARGS="--tags accounting"   # only this play
make ansible-slurm                            # everything: changed=0
```

```
slurmcluster    default    root
slurmcluster    root                 <- the built-in root account, made by Slurm
slurmcluster    root       root
```

**Try it** (on slurm-master):

